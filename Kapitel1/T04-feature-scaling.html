⚖️ Feature Scaling

Gradient Descent, k-NN und SVM reagieren empfindlich auf unterschiedliche Feature-Größenordnungen. RobustScaler, Power Transformations und der richtige Scaler für jede Situation.

🎯
Einleitung
Ziel & Kontext

Feature Scaling vs. Normalisierung?

Die Begriffe werden oft vermischt. Feature Scaling ist der Oberbegriff — er umfasst alle Transformationen, die Features auf vergleichbare Größenordnungen bringen. Thema 2 hat Min-Max und Z-Score eingeführt. Dieses Thema vertieft das und fügt zwei wichtige Methoden hinzu:

🦾 1️⃣ RobustScaler

Skaliert mit Median & IQR — robust gegen Ausreißer. → Zu Methode 1

📐 2️⃣ Power Transform

Korrigiert schiefe Verteilungen (Log, Box-Cox, Yeo-Johnson). → Zu Methode 2

Am Ende vergleichen wir alle Scaler aus K1 direkt im Abschnitt Vergleich.

Warum Gradient Descent Scaling braucht

Gradient Descent minimiert eine Loss-Funktion durch iterative Schritte in Richtung des steilsten Abstiegs. Ohne Scaling haben Features sehr unterschiedliche Größenordnungen — das führt zu einer länglichen, elliptischen Loss-Landschaft:

❌ Ohne Scaling

🥚

Längliche Ellipse: der Gradient zeigt meist in die "falsche" Richtung → Zig-Zag-Konvergenz → viele Iterationen nötig.

x₁: Alter [18–80]
x₂: Einkommen [20k–200k]
→ x₂ dominiert komplett

✅ Mit Scaling

⭕

Kreisförmige Konturlinien: Gradient zeigt direkt zum Minimum → schnelle, direkte Konvergenz.

x₁': Alter [0–1]
x₂': Einkommen [0–1]
→ beide Features gleich gewichtet

Algorithmen und ihr Scaling-Bedarf

AlgorithmusScaling nötig?Warum
k-NN✅ JaBerechnet Euklidische Abstände — dominante Features übernehmen komplett
SVM✅ JaMaximiert Margin — dieser hängt von den Einheiten der Features ab
Logistische Regression✅ JaGradient Descent konvergiert schneller; Koeffizienten vergleichbar
Neuronale Netze✅ JaGradient Descent + Aktivierungsfunktionen (z.B. Sigmoid sättigt bei großen Werten)
PCA✅ JaEigenvektoren werden von Varianz dominiert — Feature mit größerem Bereich dominiert
k-Means✅ JaDistanz-basiert, wie k-NN
Lineare Regression⚠️ OptionalErgebnis gleichwertig; hilfreich für Interpretation und GD-basiertes Lösen
Entscheidungsbaum❌ NeinSplit-Regeln basieren auf Schwellenwerten, nicht Abständen
Random Forest / XGBoost❌ NeinEnsemble aus Bäumen — monotone Transformationen ändern nichts
Naive Bayes❌ NeinProbabilistisch; Annahmen gelten per Feature unabhängig
🔗 Querverweis

Skalierung ist Pflicht für distanzbasierte Verfahren: K3-T01 · SVM-Hyperebene und K4-T01 · k-Means liefern ohne Scaling stark verzerrte Ergebnisse.

Kernfrage

Welcher Algorithmus braucht Scaling — und welcher nicht? Wie wähle ich den richtigen Scaler?

Lernziel

Du kennst alle gängigen Scaling-Methoden, weißt welche für welchen Algorithmus geeignet ist und kannst die Pipeline korrekt aufbauen.

1
Skalierung mit Ausreißern (RobustScaler)

Skaliert mit Median und IQR (Interquartilabstand) statt Mean und Std — dadurch robust gegen Ausreißer.

🧠 Theorie ⚙️ Algorithmus 🛠️ Von Scratch 🚀 Mit sklearn
🧠
Theorie
RobustScaler — Median und IQR statt Mean und Std

Der RobustScaler ist robust gegen Ausreißer, weil er Median und IQR (Interquartilabstand) verwendet — diese werden von Extremwerten kaum beeinflusst.

RobustScaler Formel
x' = (x − Median) / IQR
IQR = Q3 − Q1 = 75. Perzentil minus 25. Perzentil Median = 50. Perzentil — nicht beeinflusst von Extremwerten

Konkretes Beispiel: Ausreißer-Vergleich

DatenpunkteStatistikStandardScaler ErgebnisRobustScaler Ergebnis
[1, 2, 3, 4, 5]μ=3, σ=1.41
Median=3, IQR=2		[−1.41, −0.71, 0, 0.71, 1.41][−1.0, −0.5, 0.0, 0.5, 1.0]
[1, 2, 3, 4, 100]μ=22, σ=39.2
Median=3, IQR=2		[−0.54, −0.51, −0.49, −0.46, +2.0][−1.0, −0.5, 0.0, 0.5, +48.5]

StandardScaler quetscht alle normalen Werte zusammen wenn ein Ausreißer dabei ist (Werte 1–4 alle zwischen −0.54 und −0.46). RobustScaler zeigt den Ausreißer klar als +48.5, lässt normale Werte aber unverzerrt.

Merksatz

RobustScaler verschiebt um den Median (statt Mean) und skaliert mit dem IQR (statt Std) — beide Statistiken sind unempfindlich gegenüber Extremwerten.

⚙️
Algorithmus
RobustScaler — Schritt für Schritt
1
Median berechnen (Fit)

Sortiere X_train und nimm den mittleren Wert (50. Perzentil).

2
IQR berechnen (Fit)

Q1 = 25. Perzentil, Q3 = 75. Perzentil. IQR = Q3 − Q1.

3
Transformieren

x' = (x − Median) / IQR für jeden Wert. Ausreißer erhalten große Werte, normale Werte bleiben kompakt.

🛠️
Von Scratch
RobustScaler selbst implementieren
🐍 1/2a — Klasse: RobustScaler_Scratch
import numpy as np

class RobustScaler_Scratch:
    """Eigene Implementierung des RobustScalers."""

    def fit(self, X):
        self.median_ = np.median(X, axis=0)
        self.q1_     = np.percentile(X, 25, axis=0)
        self.q3_     = np.percentile(X, 75, axis=0)
        self.iqr_    = self.q3_ - self.q1_
        return self

    def transform(self, X):
        return (X - self.median_) / self.iqr_

    def fit_transform(self, X):
        return self.fit(X).transform(X)

2
Schiefe Verteilungen korrigieren (PowerTransformer)

Log-, Box-Cox- und Yeo-Johnson-Transformationen machen schiefe Verteilungen symmetrischer — wichtig für lineare Modelle.

🧠 Theorie ⚙️ Algorithmus 🛠️ Von Scratch 🚀 Mit sklearn
🧠
Theorie
Power Transformations — Intuition

Viele Algorithmen (insb. Lineare Modelle) nehmen normalverteilte Features an. Wenn ein Feature stark rechtsschief ist (z.B. Einkommen, Hauspreise, Web-Traffic), hilft eine Power Transformation:

TransformationFormelFürEinschränkung
Log-Transformationx' = log(x + 1)Rechts-schiefe DatenNur x ≥ 0 (daher +1)
Box-Coxx' = (x^λ − 1)/λ  (λ≠0)Rechts-schief, optimiert λNur x > 0!
Yeo-JohnsonErweiterung von Box-CoxAlle reellen WerteKeine (empfohlen)
Sqrt-Transformationx' = √xZähldaten (Poisson)Nur x ≥ 0
Warum Log-Transformation hilft

Einkommen [20k, 50k, 100k, 500k]: Rohdaten stark rechtsschief. Log: [9.9, 10.8, 11.5, 13.1] — viel gleichmäßiger verteilt. Das macht die lineare Modellannahme realistischer und GD stabiler.

Merksatz

Power Transformations ändern die Form der Verteilung (Schiefe → Symmetrie), während Scaler wie MinMax/StandardScaler nur die Größenordnung ändern. Beides kombiniert: erst transformieren, dann skalieren.

⚙️
Algorithmus
Log-Transformation — Schritt für Schritt
1
Schiefe prüfen

Wenn Skewness > 1.0 (stark rechtschief): Log-Transform anwenden.

2
Werte +1 verschieben (falls nötig)

log(0) ist undefiniert. Wenn X enthält 0-Werte: x' = log(x + 1) (log1p).

3
Log anwenden

x' = log(x + 1) für jeden Wert. Auf Testdaten dieselbe Transformation anwenden.

4
Danach Scaler anwenden

Log-Transformation + StandardScaler ist eine typische Pipeline für stark schiefe Daten.

🛠️
Von Scratch
Log-Transformation selbst implementieren
🐍 2/2a — Klasse: LogTransformer_Scratch
class LogTransformer_Scratch:
    """Log1p-Transformation für rechts-schiefe Verteilungen."""

    def fit(self, X):
        # Prüfe ob Daten nicht-negativ sind
        if (X < 0).any():
            raise ValueError("Log-Transformation erfordert X >= 0")
        return self

    def transform(self, X):
        return np.log1p(X)   # log(x + 1) — vermeidet log(0) = -inf

    def inverse_transform(self, X_log):
        return np.expm1(X_log)  # e^x - 1 (Umkehrung von log1p)

    def fit_transform(self, X):
        return self.fit(X).transform(X)

⚠️
Box-Cox mit negativen oder null Werten

PowerTransformer(method='box-cox') erfordert zwingend x > 0. Bei x=0 oder x<0 → Fehler.

✅ Lösung: method='yeo-johnson' — funktioniert für alle reellen Zahlen, empfohlen als Standard.
Zusammenfassung

PowerTransformer(method='yeo-johnson') findet automatisch das optimale λ pro Feature und transformiert + skaliert in einem Schritt. Bei λ≈0.09 (Einkommen) entspricht das fast einer Log-Transformation.

Pipelines vergleichen: RobustScaler vs. PowerTransformer

Beide Methoden werden mit einem SVC-Klassifikator kombiniert und auf denselben Daten (X_train/X_test aus Methode 1) evaluiert:

🐍 Schritt — Pipelines vergleichen (Scaler + SVC)
from sklearn.pipeline import Pipeline
from sklearn.svm import SVC
from sklearn.metrics import accuracy_score

pipe_std = Pipeline([
    ('scaler', StandardScaler()),
    ('clf', SVC(kernel='rbf', C=1.0, random_state=42))
])

pipe_rob = Pipeline([
    ('scaler', RobustScaler()),
    ('clf', SVC(kernel='rbf', C=1.0, random_state=42))
])

pipe_pow = Pipeline([
    ('scaler', PowerTransformer(method='yeo-johnson')),
    ('clf', SVC(kernel='rbf', C=1.0, random_state=42))
])

for name, pipe in [('StandardScaler', pipe_std),
                   ('RobustScaler',   pipe_rob),
                   ('PowerTransformer', pipe_pow)]:
    pipe.fit(X_train, y_train)
    acc = accuracy_score(y_test, pipe.predict(X_test))
    print(f"{name:<20}: Accuracy = {acc:.4f}")
▶ Ausgabe
StandardScaler      : Accuracy = 0.8500
RobustScaler        : Accuracy = 0.8500
PowerTransformer    : Accuracy = 0.9000

PowerTransformer schneidet hier am besten ab, weil es die schiefe Einkommensverteilung direkt korrigiert — RobustScaler reduziert nur den Einfluss des Ausreißers, ändert aber nichts an der Form der Verteilung.

⚠️
Scaling für Entscheidungsbäume/Random Forest

Für Random Forest oder Gradient Boosting ist Scaling unnötig — Split-Regeln basieren auf Schwellenwerten, nicht Abständen. Es schadet nicht, ist aber Rechenaufwand ohne Nutzen.

✅ Scaling nur für: k-NN, SVM, Lineare Modelle, Neuronale Netze, PCA, k-Means
Zusammenfassung

Feature Scaling wählen: Normal/keine Ausreißer → StandardScaler. Ausreißer vorhanden → RobustScaler. Schiefe Verteilung → PowerTransformer(yeo-johnson). Pixelwerte/fester Bereich → MinMaxScaler. Tree-based Modelle → kein Scaling nötig.
