🔢 Encoding: Kategorien → Zahlen

ML-Algorithmen rechnen mit Zahlen — aber Daten enthalten oft Text-Kategorien. Label-Encoding, Ordinal-Encoding und One-Hot-Encoding: wann was und warum.

🎯
Einleitung
Ziel & Kontext

Das Problem: Kategoriale Variablen

Du hast ein Feature Farbe mit Werten ["rot", "blau", "grün"]. Ein Algorithmus wie SVM oder k-NN kann damit nicht rechnen — er braucht Zahlen. Encoding ist die Lösung.

Die Kernfrage

Wie kodiere ich Kategorien in Zahlen, ohne dem Algorithmus falsche Ordnungen oder Abstände zu vermitteln?

Es gibt drei grundlegende Ansätze — und die Wahl des falschen kann das Modell systematisch falsche Zusammenhänge lernen lassen. Jede Methode wird im Folgenden komplett von Theorie bis sklearn durchgegangen:

🔢 1️⃣ Label-Encoding

Für die Zielvariable y — jede Klasse bekommt eine Zahl. → Zu Methode 1

📶 2️⃣ Ordinal-Encoding

Für ordinale Features mit echter Reihenfolge (klein < mittel < groß). → Zu Methode 2

0️⃣1️⃣ 3️⃣ One-Hot-Encoding

Für nominale Features ohne Ordnung (Farbe, Stadt). → Zu Methode 3

Am Ende vergleichen wir alle drei direkt im Abschnitt Vergleich und kombinieren sie mit einem ColumnTransformer.

Lernziel

Du weißt, wann Label-, Ordinal- und One-Hot-Encoding verwendet wird, und kannst alle drei selbst implementieren und mit sklearn anwenden.

1
Label-Encoding (LabelEncoder)

Jeder Kategorie wird eine ganze Zahl zugewiesen — gedacht für die Zielvariable y.

🧠 Theorie ⚙️ Algorithmus 🛠️ Von Scratch 🚀 Mit sklearn
🧠
Theorie
Label-Encoding — Intuition

Jeder Kategorie wird eine ganze Zahl zugewiesen: rot → 0, blau → 1, grün → 2.

OriginalLabel-Encoded
rot0
blau1
grün2
Problem: Künstliche Ordnung

Label-Encoding suggeriert dem Algorithmus: grün (2) > blau (1) > rot (0) und Abstand(rot,grün) = 2× Abstand(rot,blau). Bei Farben ist das sinnlos! Nur für die Zielvariable y (Klassen-Label) ist LabelEncoder korrekt.

OrdinalEncoder vs. LabelEncoder

OrdinalEncoder arbeitet auf Features (2D-Matrix X), LabelEncoder auf der Zielvariable (1D-Vektor y). Verwende niemals LabelEncoder für Features X — er hat keine Möglichkeit, die gewünschte Reihenfolge festzulegen.

Merksatz

LabelEncoder = Mapping Kategorie → Zahl für y. Niemals für Features X verwenden, da die entstehende Ordnung/Abstände willkürlich sind.

⚙️
Algorithmus
Label-Encoding — Schritt für Schritt
1
Unique-Kategorien ermitteln (Fit)

Sammle alle einzigartigen Werte und sortiere sie: {"blau", "grün", "rot"} → alphabetisch.

2
Mapping erstellen

Index = Reihenfolge: {"blau": 0, "grün": 1, "rot": 2}

3
Werte ersetzen (Transform)

["rot","blau","grün"] → [2, 0, 1]

🛠️
Von Scratch
LabelEncoder selbst implementieren
🐍 1/2 — Klasse: LabelEncoder_Scratch (für y)
import numpy as np

class LabelEncoder_Scratch:
    """Für Zielvariable y. Lernt Klassen und encodet/dekodet sie."""

    def fit(self, y):
        self.classes_ = np.unique(y)                         # Sortiert, eindeutig
        self.mapping_ = {c: i for i, c in enumerate(self.classes_)}
        self.inv_map_ = {i: c for c, i in self.mapping_.items()}
        return self

    def transform(self, y):
        return np.array([self.mapping_[val] for val in y])

    def fit_transform(self, y):
        return self.fit(y).transform(y)

    def inverse_transform(self, y_encoded):
        return np.array([self.inv_map_[val] for val in y_encoded])

Einblick

Der Kern ist ein Dictionary-Mapping: Kategorie → Zahl, plus die Umkehrabbildung für inverse_transform. Genau dieses Muster taucht bei allen drei Encodern wieder auf.

Zusammenfassung

LabelEncoder kodiert die Zielvariable y als ganze Zahlen 0..K-1 und kann mit inverse_transform zurückübersetzen. Für Features X: niemals LabelEncoder — stattdessen Methode 2 oder 3.

2
Ordinal-Encoding (OrdinalEncoder)

Ähnlich wie Label-Encoding, aber die Reihenfolge wird explizit festgelegt — für ordinale Features X wie Größe, Note oder Zufriedenheit.

🧠 Theorie ⚙️ Algorithmus 🛠️ Von Scratch 🚀 Mit sklearn
🧠
Theorie
Ordinal-Encoding — Intuition
OriginalOrdinal-EncodedKorrekt, weil
klein0klein < mittel < groß < XL
Diese Ordnung existiert wirklich!
mittel1
groß2
XL3
OrdinalEncoder vs. LabelEncoder

OrdinalEncoder arbeitet auf Features (2D-Matrix X) und erlaubt eine explizit definierte Reihenfolge je Spalte — anders als LabelEncoder, der einfach alphabetisch sortiert.

Merksatz

Ordinal-Encoding ist nur korrekt, wenn die numerische Ordnung der echten, inhaltlichen Ordnung entspricht (klein < mittel < groß < XL).

⚙️
Algorithmus
Ordinal-Encoding — Schritt für Schritt
1
Reihenfolge definieren (Fit)

Explizite Liste: ["klein", "mittel", "groß", "XL"]. Die Position bestimmt den Code.

2
Mapping erstellen

{"klein": 0, "mittel": 1, "groß": 2, "XL": 3}

3
Werte ersetzen (Transform)

["groß","klein","XL"] → [2, 0, 3] — die numerische Ordnung spiegelt die echte wider.

🛠️
Von Scratch
OrdinalEncoder selbst implementieren
🐍 1/2 — Klasse: OrdinalEncoder_Scratch (für ordinale Features)
class OrdinalEncoder_Scratch:
    """Für ordinale Features X mit bekannter Reihenfolge."""

    def __init__(self, categories):
        # categories: Liste von Listen, eine pro Feature-Spalte.
        # Die Reihenfolge bestimmt den Code (Index in der Liste).
        self.categories = categories

    def fit(self, X):
        self.mappings_ = []
        for i, cats in enumerate(self.categories):
            self.mappings_.append({c: j for j, c in enumerate(cats)})
        return self

    def transform(self, X):
        result = np.zeros(X.shape, dtype=float)
        for i, m in enumerate(self.mappings_):
            result[:, i] = [m[val] for val in X[:, i]]
        return result

    def fit_transform(self, X):
        return self.fit(X).transform(X)

OrdinalEncoder:

handle_unknown

Mit handle_unknown='use_encoded_value', unknown_value=np.nan werden unbekannte Kategorien (im Test, aber nicht im Training) zu NaN statt einen Fehler zu werfen.

Zusammenfassung

OrdinalEncoder kodiert Features X gemäß einer explizit definierten Reihenfolge. Wichtig: categories immer selbst angeben, sonst wird alphabetisch sortiert — das entspricht meist nicht der gewünschten Ordnung.

3
One-Hot-Encoding (OneHotEncoder)

Für jede Kategorie wird eine binäre Spalte erstellt (0 oder 1) — für nominale Features ohne Ordnung.

🧠 Theorie ⚙️ Algorithmus 🛠️ Von Scratch 🚀 Mit sklearn
🧠
Theorie
One-Hot-Encoding — Intuition

Für jede Kategorie wird eine binäre Spalte erstellt (0 oder 1). Keine falsche Ordnung mehr.

Originalrotblaugrün
rot100
blau010
grün001

Die Dummy-Variable-Trap (Multikollinearität)

Bei 3 Kategorien sind nur 2 Spalten unabhängig — die dritte ergibt sich immer aus den anderen zwei (wenn rot=0 und blau=0, muss grün=1 sein). Diese Redundanz heißt Dummy-Variable-Trap.

❌ 3 Spalten (redundant)
rot=[1,0,0], blau=[0,1,0], grün=[0,0,1]
Problem bei linearen Modellen (Singulärmatrix)
✅ 2 Spalten (drop_first=True)
blau=[0,1,0], grün=[0,0,1]
rot ist implizit: wenn blau=0 und grün=0
Wann drop_first?

Für lineare Modelle (Logistische Regression, Lineare Regression): drop='first' ist wichtig. Für Tree-based Modelle (RF, XGBoost): kein Unterschied. Für Interpretation: drop_first kann sinnvoll sein. Im Zweifel: beide ausprobieren.

Bonus: Bag-of-Words für Text

Wenn eine Kategorie ein ganzer Text ist (z.B. Produktbeschreibung), funktioniert OHE nicht. Bag-of-Words zählt, wie oft jedes Wort im Text vorkommt — und erstellt einen Feature-Vektor der Länge |Vokabular|. sklearn.feature_extraction.text.CountVectorizer implementiert das. Achtung: Wortstellung geht verloren, und das Feature kann sehr hochdimensional werden.

⚙️
Algorithmus
One-Hot-Encoding — Schritt für Schritt
1
Unique-Kategorien ermitteln (K Stück)

Bestimme alle K einzigartigen Werte aus den Trainingsdaten.

2
K neue binäre Spalten erstellen

Eine Spalte pro Kategorie, benannt nach der Kategorie.

3
Jede Zeile kodieren

Setze 1 in der Spalte der zutreffenden Kategorie, 0 in allen anderen.

4
Optional: erste Spalte droppen

Zur Vermeidung der Dummy-Variable-Trap bei linearen Modellen: eine Spalte entfernen (sie ist redundant).

Beispiel: OHE Schritt für Schritt

SchrittErgebnis
Trainingsdaten["rot", "blau", "grün", "rot"]

Erstelle 3 SpaltenSpalten: blau, grün, rot
Enkodierung "rot"[0, 0, 1]
Enkodierung "blau"[1, 0, 0]
Enkodierung "grün"[0, 1, 0]

🐍 1/2 — Klasse: OneHotEncoder_Scratch (für nominale Features)
class OneHotEncoder_Scratch:
    """Für nominale Features X ohne Reihenfolge."""

    def fit(self, X_col):
        self.categories_ = np.unique(X_col)
        self.n_categories_ = len(self.categories_)
        self.mapping_ = {c: i for i, c in enumerate(self.categories_)}
        return self

    def transform(self, X_col, drop_first=False):
        n = len(X_col)
        result = np.zeros((n, self.n_categories_), dtype=int)
        for i, val in enumerate(X_col):
            if val in self.mapping_:
                result[i, self.mapping_[val]] = 1
        if drop_first:
            result = result[:, 1:]
        return result

    def fit_transform(self, X_col, drop_first=False):
        return self.fit(X_col).transform(X_col, drop_first)

📊 Visualisierung — One-Hot-Matrix als Heatmap

ColumnTransformer: Gemischte Daten (numerisch + kategorial)

Datensatz mit drei unterschiedlichen Spaltentypen: Alter (numerisch), Farbe (nominal), Größe (ordinal) — alle drei Encoder kombiniert in einer Pipeline.

🐍 Schritt 1 — Daten anlegen
import numpy as np

X_train = np.array([
    [25, "rot",  "klein"],
    [32, "blau", "groß"],
    [28, "grün", "mittel"],
    [45, "rot",  "XL"]
], dtype=object)
y_train = np.array([0, 1, 0, 1])

X_test = np.array([
    [30, "blau", "mittel"],
    [50, "grün", "groß"]
], dtype=object)

print("X_train Spalten: Alter | Farbe | Größe")
print(X_train)
🐍 Schritt 2 — ColumnTransformer: pro Spalte eine Transformation
from sklearn.compose import ColumnTransformer
from sklearn.preprocessing import OneHotEncoder, StandardScaler, OrdinalEncoder

preprocessor = ColumnTransformer(transformers=[
    ('num',     StandardScaler(),                                 [0]),  # Spalte 0: numerisch
    ('nominal', OneHotEncoder(drop='first', sparse_output=False), [1]),  # Spalte 1: nominal
    ('ordinal', OrdinalEncoder(categories=[["klein", "mittel", "groß", "XL"]]), [2]),  # Spalte 2: ordinal
])

X_transformed = preprocessor.fit_transform(X_train)
print("Transformiert (Alter | blau | grün | Größe):")
print(X_transformed.round(2))
▶ Ausgabe
Transformiert (Alter | blau | grün | Größe):
[[-1.178  0.     1.     0.   ]
 [ 0.     1.     0.     2.   ]
 [-0.588  0.     0.     1.   ]
 [ 1.765  0.     1.     3.   ]]
🐍 Schritt 3 — Pipeline: Preprocessing + Modell
from sklearn.pipeline import Pipeline
from sklearn.linear_model import LogisticRegression

pipe = Pipeline([
    ('prep', preprocessor),
    ('clf', LogisticRegression(random_state=42))
])

pipe.fit(X_train, y_train)
pred = pipe.predict(X_test)

print("Vorhergesagte Klassen:", pred)
▶ Ausgabe
Vorhergesagte Klassen: [1 1]

⚠️
LabelEncoder für Features X verwenden

LabelEncoder ist nur für die Zielvariable y gedacht. Er bietet keine Möglichkeit, die Reihenfolge zu definieren.

✅ Features: OrdinalEncoder (ordinal) oder OneHotEncoder (nominal) · Zielvariable: LabelEncoder
⚠️
Unbekannte Kategorien in Testdaten

Wenn im Test eine Kategorie auftaucht, die im Training nicht vorkam, wirft sklearn standardmäßig einen Fehler.

✅ OneHotEncoder: handle_unknown='ignore' → unbekannte Kategorie = alles 0. OrdinalEncoder: handle_unknown='use_encoded_value', unknown_value=np.nan
⚠️
chi2-Test mit negativen Werten

Die Score-Funktion chi2 in SelectKBest erwartet nicht-negative Werte (X ≥ 0). Nach One-Hot-Encoding ist das erfüllt. Aber nach einem StandardScaler (der negative Werte erzeugt) nicht!

✅ Reihenfolge bei chi2: Encoding → SelectKBest(chi2). Nicht: StandardScaler → SelectKBest(chi2).
Zusammenfassung

Drei Encoder für drei Situationen: LabelEncoder für Zielvariable y, OrdinalEncoder für Features mit echter Reihenfolge, OneHotEncoder für nominale Features ohne Reihenfolge. ColumnTransformer kombiniert alle in einer einzigen sauberen Pipeline.
