📈 Overfitting & Underfitting

Das Generalisierungsproblem: Wann lernt ein Modell zu wenig — wann zu viel? Und wie erkennt man den Unterschied?

Stufe 1

🎯 Ziel & Kontext

Die Analogie: Lernen für die Prüfung

Stell dir drei Schüler vor, die für eine Mathe-Prüfung lernen:

😴

Schüler A – Underfitting

Hat kaum gelernt. Versteht nicht mal die Grundregeln. Scheitert an Trainingsaufgaben UND Prüfung.

🎯

Schüler B – Just Right

Hat das Konzept verstanden. Löst bekannte UND neue Aufgaben gut. Generalisiert.

📖

Schüler C – Overfitting

Hat alle Übungsaufgaben auswendig gelernt. Perfekt auf Training — versagt bei neuen Aufgaben.

Das Ziel von ML: Ein Modell trainieren, das auf ungesehenen Daten gut funktioniert — nicht nur auf den Trainingsdaten.
Stufe 2

🧠 Theorie & Intuition

Wie man Overfitting/Underfitting erkennt

Man vergleicht Training Accuracy mit Test Accuracy:

SituationTrain AccTest AccDiagnose
Modell zu einfach Niedrig (~60%) Niedrig (~59%) Underfitting
Ideales Modell Hoch (~95%) Hoch (~93%) Gute Generalisierung
Modell zu komplex Sehr hoch (~99%) Niedrig (~72%) Overfitting

Ursachen und Lösungen

Underfitting (High Bias)Overfitting (High Variance)
UrsacheModell zu simpel, Features fehlenModell zu komplex, zu wenig Daten
LösungKomplexeres Modell, mehr FeaturesRegularisierung, mehr Daten, Dropout
BeispielLineare Kurve durch quadratische DatenGrad-15 Polynom durch 10 Datenpunkte
sklearn fixGrad erhöhen, mehr Estimatorsmax_depth, C, alpha kleiner
📉 Underfitting (High Bias)

Modell ist zu simpel, um das Muster in den Daten zu erfassen. Train- UND Test-Accuracy sind beide niedrig und liegen nah beieinander. Lösung: komplexeres Modell, mehr Features, weniger Regularisierung.

↔
📈 Overfitting (High Variance)

Modell ist zu komplex und merkt sich die Trainingsdaten statt das zugrundeliegende Muster zu lernen. Train-Accuracy ist sehr hoch, Test-Accuracy fällt stark ab. Lösung: Regularisierung, mehr Daten, einfacheres Modell.

Die Learning Curve

Eine Learning Curve plottet Train/Test-Accuracy gegen die Anzahl der Trainingsdaten:

Underfitting: Beide Kurven konvergieren auf niedrigem Niveau
Overfitting: Großer Gap zwischen Train (hoch) und Test (niedrig)
Good Fit: Kurven konvergieren auf hohem Niveau

Regularisierung: Die wichtigste Gegenstrategie

Regularisierung bestraft große Modellgewichte und zwingt das Modell zu Einfachheit:

MethodeWas sie tutParameter
L2 (Ridge)Straft große Gewichte quadratischalpha oder C

⚙️ Overfitting diagnostizieren — Schritt für Schritt

1
Modell trainieren & Train/Test Accuracy messen

Wenn Train Acc » Test Acc → Overfitting. Wenn beide niedrig → Underfitting.

2
Modellkomplexität variieren (Validation Curve)

Einen Hyperparameter (z.B. max_depth) von klein bis groß variieren. Train und Test Accuracy plotten.

3
Sweet Spot finden

Den Punkt wählen, wo Test Accuracy maximal ist — vor dem Overfitting-Bereich.

4
Cross-Validation für robuste Schätzung

Nicht nur eine Train/Test-Aufteilung — CV gibt stabilere Metriken (nächstes Thema).

Stufe 4

🛠️ Von Scratch: Overfitting sichtbar machen

Wir erzeugen Daten und zeigen wie Polynomgrad Overfitting verursacht:

🐍 1/2a — Funktion: polynomial_fit_and_evaluate 
import numpy as np

def polynomial_fit_and_evaluate(X_train, y_train, X_test, y_test, degree):
    """Polynom-Regression Grad 'degree' von Scratch (ohne sklearn)."""
    # Vandermonde-Matrix aufbauen: [1, x, x², x³, ...]
    def make_features(X, d):
        return np.column_stack([X**i for i in range(d+1)])

    X_tr = make_features(X_train, degree)
    X_te = make_features(X_test, degree)

    # Kleinste Quadrate: w = (XᵀX)⁻¹ Xᵀy
    w = np.linalg.lstsq(X_tr, y_train, rcond=None)[0]

    train_mse = np.mean((X_tr @ w - y_train)**2)
    test_mse  = np.mean((X_te @ w - y_test)**2)
    return train_mse, test_mse

Jetzt erzeugen wir Daten (y = sin(2πx) + Rauschen) und testen verschiedene Polynomgrade:

🐍 1/2b — Test: Polynomgrade vergleichen 
np.random.seed(42)
X_all = np.linspace(0, 1, 100)
y_all = np.sin(2 * np.pi * X_all) + np.random.normal(0, 0.3, 100)

# 20 Trainings-, 80 Testpunkte
idx = np.random.choice(100, 20, replace=False)
X_train, y_train = X_all[idx], y_all[idx]
X_test  = np.delete(X_all, idx)
y_test  = np.delete(y_all, idx)

print(f"{'Grad':>6} | {'Train MSE':>10} | {'Test MSE':>10} | Diagnose")
print("-" * 50)
for d in [1, 3, 5, 9, 15]:
    tr_mse, te_mse = polynomial_fit_and_evaluate(
        X_train, y_train, X_test, y_test, d
    )
    if tr_mse < 0.05 and te_mse > 0.2:
        diag = "⚠️  OVERFITTING"
    elif tr_mse > 0.15:
        diag = "📉 Underfitting"
    else:
        diag = "✅ OK"
    print(f"{d:>6} | {tr_mse:>10.4f} | {te_mse:>10.4f} | {diag}")

🚀 Overfitting mit sklearn diagnostizieren

🐍 Schritt 1 — Daten erzeugen & splitten 
from sklearn.datasets import make_classification
from sklearn.model_selection import train_test_split

X, y = make_classification(
    n_samples=300,
    n_features=10,
    n_informative=5,
    random_state=42
)
X_train, X_test, y_train, y_test = train_test_split(
    X,
    y,
    test_size=0.3,
    random_state=42
)

print(f"X_train: {X_train.shape}, X_test: {X_test.shape}")

X_train: (210, 10), X_test: (90, 10)
🐍 Schritt 2 — Validation Curve über max_depth 
from sklearn.tree import DecisionTreeClassifier
from sklearn.model_selection import validation_curve

depths = range(1, 21)
train_scores, val_scores = validation_curve(
    DecisionTreeClassifier(random_state=42),
    X_train,
    y_train,
    param_name='max_depth',
    param_range=depths,
    cv=5,
    scoring='accuracy'
)

print(f"{'max_depth':>10} | {'Train Acc':>10} | {'Val Acc':>10} | Diagnose")
print("-" * 55)
for d, tr, va in zip(depths,
                     train_scores.mean(axis=1),
                     val_scores.mean(axis=1)):
    gap = tr - va
    if gap > 0.1:
        diag = "⚠️  Overfitting"
    elif tr < 0.8:
        diag = "📉 Underfitting"
    else:
        diag = "✅ OK"
    print(f"{d:>10} | {tr:>10.2%} | {va:>10.2%} | {diag}")

Die Train-Kurve steigt schnell auf 100% und bleibt dort. Die Val-Kurve steigt zunächst (von 75% auf ~82% bei depth=2), fällt danach aber kontinuierlich ab auf ~75%. Der Sweet Spot liegt genau am Maximum der Val-Kurve — hier bei max_depth=2. Rechts davon öffnet sich eine immer größere Lücke zwischen den Kurven = Overfitting.

Learning Curve mit sklearn

🐍 Python — Learning Curve 
from sklearn.model_selection import learning_curve
from sklearn.svm import SVC

train_sizes, train_scores, val_scores = learning_curve(
    SVC(kernel='rbf'),
    X,
    y,
    train_sizes=np.linspace(0.1, 1.0, 10),
    cv=5,
    scoring='accuracy'
)

print("Trainings-Größe | Train Acc | Val Acc")
for size, tr, va in zip(train_sizes,
                        train_scores.mean(axis=1),
                        val_scores.mean(axis=1)):

Die Val-Accuracy steigt von 74% (bei 24 Samples) kontinuierlich auf 87% (bei 240 Samples), während die Train-Accuracy stabil bei ~90% bleibt. Die Lücke zwischen beiden Kurven schrumpft mit mehr Daten — ein klares Zeichen, dass dieses Modell von mehr Trainingsdaten profitieren würde. Wenn die Val-Kurve schon bei wenigen Samples ihr Plateau erreicht hätte, würde mehr Daten nicht helfen.
